01
IDENTITÄT

Ein AI-Agent braucht eine eigene, nachvollziehbare Identität

Wenn ein Agent unter der Identität eines Menschen läuft, ist im Log nicht mehr unterscheidbar, wer wirklich gehandelt hat.

Mensch-Login geteilt
→
Agent handelt "als" der Mensch
→
Keine Unterscheidung im Audit-Log
Vertiefung öffnen

Eigene Service-Identität als Grundprinzip

Ein AI-Agent, der Dateien liest oder E-Mails verschickt, sollte eine eigene Service-Identität mit eigenen, bewusst zugewiesenen Berechtigungen haben — nicht die Zugangsdaten eines Menschen mitbenutzen. Das ist dieselbe Logik wie bei jedem anderen automatisierten System (z.B. einem Cronjob oder einer CI/CD-Pipeline).

02
LEAST PRIVILEGE

Warum "Vollzugriff, um sicherzugehen" die falsche Antwort ist

Je mehr ein Agent darf, desto größer der Schaden, wenn er durch einen Fehler oder eine Manipulation missbraucht wird.

AnsatzVorteilRisiko
Vollzugriff "auf Nummer sicher"Nie eine fehlende Berechtigung als FehlerquelleMaximaler Schaden bei Fehlverhalten oder Prompt Injection
Least Privilege (nur was nötig ist)Schaden im Missbrauchsfall begrenztMehr initialer Konfigurationsaufwand
BAIS-Muster

Für jeden Agenten-Zugriff explizit fragen: "Welche einzelnen Aktionen muss dieser Agent wirklich ausführen können?" — nicht: "Welche Rolle in unserem System kommt dem am nächsten?"

BEKANNTER FALL · MICROSOFT 365 COPILOT

Copilot findet Dateien, die technisch freigegeben, aber nie gemeint waren

Mehrere Sicherheitsanbieter (u.a. Varonis) und auch Microsoft selbst wiesen darauf hin, dass Copilot durch seine Such- und Zusammenfassungsfunktion Dokumente auffindbar macht, die zwar formal für einen breiten Nutzerkreis freigegeben waren (z.B. "jeder im Unternehmen"), aber praktisch nie gefunden oder gelesen wurden — bis ein AI-Assistent gezielt danach fragen konnte. Microsoft empfiehlt seitdem ausdrücklich, Berechtigungen vor einem Copilot-Rollout zu bereinigen.

Bekannter Fall · vielfach dokumentiert seit 2023/2024
0neue technische Schwachstellen nötig — bestehende Überberechtigung reichte aus
Warum das wichtig ist

Das Tool selbst muss nicht "gehackt" werden — es macht nur sichtbar, was durch jahrelang gewachsene, nie aufgeräumte Berechtigungen längst zugänglich war.

05
VORBEREITUNG

Berechtigungen vor Rollout aufräumen, nicht danach

Ein AI-Rollout ist der beste Zeitpunkt, bestehende Zugriffsrechte zu bereinigen — nicht der Zeitpunkt, an dem man sie zum ersten Mal wirklich braucht.

SchrittZiel
BestandsaufnahmeWer/was hat aktuell Zugriff auf welche Datenquellen?
BereinigungÜberflüssige "jeder im Unternehmen"-Freigaben entfernen
NeuvergabeAgenten-Zugriffe gezielt nach Least Privilege (Lektion 02) einrichten

GOVERNANCE

Wer darf einem Agenten ein neues Werkzeug geben?

Antrag auf neue Berechtigung → Prüfung durch Security (Least Privilege) → Freigabe durch AI Owner/Compliance → dokumentiert im Audit-Trail
