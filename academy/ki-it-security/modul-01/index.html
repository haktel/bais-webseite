Warum das für Security relevant ist

Ein Modell kann keine Datenbank "hacken", auf die es keinen Zugriff bekommen hat. Aber alles, was in sein Kontextfenster gelangt — auch über ein Dokument, eine Webseite oder ein Tool-Ergebnis — wird faktisch Teil dessen, was das Modell "sieht" und potenziell in seiner Ausgabe verwendet. Das ist der Kern jeder Prompt-Injection-Diskussion in Modul 03.

03
BETRIEBSMODELL

Self-hosted, API und SaaS bedeuten unterschiedliche Kontrolle

Dieselbe Modell-Familie kann völlig unterschiedliche Datenschutz-Eigenschaften haben, je nachdem, wie sie betrieben wird.

ModellWo laufen die DatenKontrolle
Consumer-SaaS (z.B. öffentliches Chat-Interface)Anbieter-Cloud, oft globale InfrastrukturGering, abhängig von AGB/Einstellungen
Business-/API-VertragMeist vertraglich zugesicherte Region, oft ohne TrainingsnutzungMittel bis hoch, vertraglich geregelt
Self-hosted / Open-Weight-ModellEigene InfrastrukturVollständig, aber Betrieb liegt komplett in eigener Verantwortung
Vertiefung öffnen
Wichtig

"Self-hosted" bedeutet volle Kontrolle über Daten — aber auch volle Verantwortung für Patches, Absicherung und Betrieb. Es ist kein Sicherheits-Freifahrtschein, nur eine andere Verantwortungsverteilung.

04
RAG

Retrieval-Augmented Generation: eine nützliche, aber zusätzliche Angriffsfläche

RAG-Systeme holen bei jeder Anfrage passende Dokumente aus einer eigenen Wissensbasis — das ist mächtig, aber jede Quelle im Index ist potenziell Teil des Kontextfensters.

Nutzeranfrage → Suche in Dokumenten-Index → relevante Passagen ins Kontextfenster → Modell generiert Antwort
Vertiefung öffnen

Zwei Fragen, die RAG-Betreiber sich stellen müssen

Erstens: Wer darf Dokumente in den Index einspeisen — nur geprüfte interne Quellen, oder auch von außen kommende Inhalte (E-Mails, hochgeladene Dateien)? Zweitens: Respektiert die Suche bestehende Zugriffsrechte, oder kann ein Nutzer über den Umweg RAG Dokumente "sehen", auf die er eigentlich keinen direkten Zugriff hätte?

BEKANNTER FALL · SAMSUNG

Vertraulicher Quellcode landet in ChatGPT

2023 wurde bekannt, dass Samsung-Mitarbeitende vertraulichen Halbleiter-Quellcode und interne Meeting-Notizen in ein öffentliches ChatGPT-Interface eingaben. Aus Architektursicht: die Daten überschritten die Vertrauensgrenze am Eingabepunkt (Lektion 02) — Richtung Anbieter-Infrastruktur, ohne vertragliche Zusicherung zur Nichtnutzung für Training. Samsung untersagte daraufhin intern die Nutzung öffentlicher generativer KI-Tools auf Firmengeräten.
