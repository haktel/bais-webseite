01
MODULARITY

Copy-Paste-Divergenz'i durdur

Aynı normalization kodu 12 workflow'da varsa, aslında 12 bakım noktası vardır.

Copy-Paste

Normalize Lead v1, v1.1, v1.3... farklı davranışlar.

Reusable Component

Bir Normalize Lead Contract; tüm caller'lar aynı logic.

Vertiefung öffnen

Reuse sadece daha az node değildir

Asıl kazanç: tek contract, tek test seti, tek owner, tek bugfix ve kontrollü change management. Ancak trivial tek-seferlik logic'i zorla sub-workflow yapmak da over-engineering olabilir.

Extraction Rule

Logic tekrar ediyorsa, bağımsız test edilebiliyorsa ve açık input/output sınırı varsa component adayıdır.

03
INPUT CONTRACT

Workflow Input Schema alan adlarını ve tiplerini belirler; Parent mapping ile sadece ihtiyaç duyulan veriyi geçirir.

→ CONTRACT →

Vertiefung öffnen

Contract aynı zamanda data-minimization boundary'dir

Child normalize etmek için internalSecret bilmiyorsa bu alanı göndermeyin. Bu hem coupling hem data leak riskini azaltır.

Type Contract

string beklenen alan object gelirse hata erken görünmeli; downstream'de gizli TypeError olarak değil.

04
OUTPUT / ERROR CONTRACT

Success kadar failure shape de stabil olmalı

Component'in output'u caller tarafından parse edilebilir ve versionlanabilir olmalı.

Stable Success
{"valid":true,
 "contractVersion":"1.0",
 "lead":{...}}
Stable Validation
{"valid":false,
 "errors":["email_invalid"],
 "lead":{...}}
Vertiefung öffnen

Business error ile system error ayrımı

Geçersiz email beklenen bir business validation olabilir; database unreachable ise system failure. Caller bu ikisini farklı route etmelidir.

Contract Test

valid her zaman boolean mı? errors her zaman array mi? contractVersion mevcut mu?

05
SYNC / ASYNC

Parent sonucu bekleyecek mi?

Wait for Sub-Workflow Completion gerçek mimari karardır.

SynchronousParent Child output'una ihtiyaç duyar; wait=true.
AsynchronousFire-and-forget; ayrı monitoring/correlation gerekir.
Vertiefung öffnen

Async coupling azaltır ama operasyon yükünü artırır

Parent 202/accepted döndükten sonra Child hata verirse kullanıcı artık Parent response üzerinden bunu göremez. Error Workflow, correlation ID ve status store gerekir.

Use Case

Normalize Lead sync; uzun PDF processing veya bulk notification async olabilir.

06
ITEM MODE

All items bir execution mı, item başına execution mı?

Modern n8n'de birçok durumda Loop Over Items + Sub-workflow run once ile explicit batching daha anlaşılırdır.

All Items100 item → 1 child execution
Loop Batch 10100 item → 10 kontrollü çağrı
Per Itemyüksek overhead / observability ihtiyacı
Vertiefung öffnen

Granularity etkileri

Execution sayısı, failure isolation, transaction boundary, rate limit ve logs, item granularity'ye bağlıdır. En küçük parçaya bölmek otomatik olarak en iyi çözüm değildir.

07
