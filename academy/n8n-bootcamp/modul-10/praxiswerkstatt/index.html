FALL 01

Copy-Paste-Divergenz · 8 Workflow, 8 Versionen

Aynı lead-normalization logic'i sekiz workflow'a kopyalandı. Birinde email lowercase, diğerinde değil; birinde phone sanitize edildi, diğerinde unutuldu.

Deine Aufgabe

  1. Hangi logic component'e çıkar?
  2. Input/output contract yaz.
  3. Caller'lar hangi field'lere güvenebilir?
  4. Component owner kim?

Break/Fix

Bir caller phone alanını beklemiyor, yeni version ekliyor. Backward-compatible mi?

Musterlösung öffnen

Reusable normalization tek component. Required input minimal. Output versioned/stable. Optional field eklemek genellikle düşük risk; required field kaldırmak/semantics değiştirmek breaking.

  1. internalSecret neden Child'a gitmemeli?
  2. Required vs optional fields?
  3. Type conversion otomatik mi explicit mi?

Parent tüm JSON'u Child'a geçiriyor. Child logları secret'ı kaydediyor. Contract boundary ile düzelt.

Musterlösung öffnen

Explicit input schema = data minimization + coupling control. Child yalnız ihtiyaç duyduğu fields'i alır; secret value component sınırını geçmez.

FALL 03

Deine Aufgabe

  1. Bu değişiklik breaking mi?
  2. Caller inventory nasıl bulunur?
  3. Parallel version ne kadar tutulur?
  4. Rollback planı?

Break/Fix

v1 production'da direkt v2 shape'e çevrildi; 13 caller fail. Safe rollout planı yaz.

Musterlösung öffnen

Yeni contract paralel yayınlanır; integration tests + caller migration; metrics gözlenir; sonra deprecation. Shared change'in blast radius'u caller count kadar olabilir.
