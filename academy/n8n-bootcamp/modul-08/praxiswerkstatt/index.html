MODUL 08 · PRAXISWERKSTATT

Dokumente sicher in Daten verwandeln

CSV, Excel, JSON und PDF sehen einfach aus, bis Encoding, Formula Injection, Scan-PDF, Dateigröße und Storage Lifecycle ins Spiel kommen. Hier entwirfst du echte Document Pipelines.

INGESTupload · download
VALIDATEtype · size · content
PARSECSV · JSON · PDF · XLSX
STOREhash · object · retention
Regel: Dateiname und Extension sind Hinweise, keine Vertrauensbeweise. Untrusted Files werden vor Parser und Storage kontrolliert.
FALL 01

CSV Import · Encoding und Dialekt

CSV-Dateien unterscheiden sich bei Delimiter, Quotes, Header und Encoding. Internationale Kundendaten machen Fehler sofort sichtbar.

Deine Aufgabe

  1. Büşra Şahin, Jörg Müller und Çağla als Testdaten nutzen.
  2. Comma vs Semicolon testen.
  3. Header fehlt: welches Schema?
  4. String-Zahlen in Number normalisieren.

Break/Fix

UTF-8 wird als falsche Codepage gelesen; Namen erscheinen verstümmelt. Fehlerbild, root cause ve fix yaz.

Musterlösung öffnen

Encoding explizit festlegen; delimiter/header kontrollieren; parse sonrası type normalization. Unicode Testdaten regression setinin parçası olsun.

FALL 02

Spreadsheet Formula Injection

Externes Textfeld =2+2, +SUM(...) oder @... ile başlıyorsa Spreadsheet beim Öffnen Formel interpretieren kann.

Deine Aufgabe

  1. Riskli başlangıç karakterlerini tanımla.
  2. Apostroph/text-type mitigation uygula.
  3. Normal -10 sayısal alan ile untrusted text farkı?
  4. Export öncesi hangi fields sanitize edilir?

Break/Fix

Customer name =HYPERLINK(...) olarak geliyor. Workflow successful ama spreadsheet riskli. Security control ekle.

Musterlösung öffnen

Untrusted string fields spreadsheet export'tan önce formula-start check ile text olarak zorlanır. Business numeric fields schema ile ayrı ele alınır.

FALL 03

PDF · Text Layer mı Scan mı?

PDF her zaman extractable text değildir. Scanned document OCR gerektirebilir; complex layout ise extraction quality problemi yaratır.

→

Deine Aufgabe

  1. Text PDF ve scan PDF nasıl ayrılır?
  2. OCR confidence düşükse?
  3. Invoice total yanlış extract edilirse impact?
  4. Human Review threshold tasarla.

Break/Fix

Parser boş text döndürüyor ama workflow success. „Empty extraction“ quality gate ekle.

Musterlösung öffnen

Parser success ≠ business success. Minimum text/expected fields validation; scanned/low-confidence document → OCR veya human review.

Filename direkt storage path olarak kullanılıyor. Path Traversal riskini kapat.

Musterlösung öffnen

Server generated object key, size/type/content validation, optional malware scan/quarantine. Original filename yalnız metadata/UX için sanitized tutulur.

Pflichtaufgabe

  2. PDF/XLSX parser seç.
  3. Required invoice fields tanımla.
  4. Object Storage ve DB metadata ayır.
  5. Retention/deletion policy tasarla.
  6. 6 security/quality tests yaz.

Ready to Teach

JSON metadata ile Binary file content neden ayrı katmanlar? Audit ve replay açısından açıkla.

Referenzlösung öffnen

Raw object immutable storage'ta; DB: objectKey, sha256, mime, size, source, parserVersion, extractionStatus. Low quality → review. Retention purpose-based; delete both metadata and object per policy.
