01
GRUNDLAGE

Was ist n8n?

n8n ist eine Workflow-Automation- und Integrationsplattform. Sie verbindet Ereignisse, Daten und Systeme zu automatisierten Abläufen.

Ereignis → Trigger → Daten → Verarbeitung → Aktion → Ergebnis
Mehr Details

n8n ersetzt nicht automatisch CRM, Datenbank oder Backend. Es sitzt häufig als Orchestrierungs- und Integrationsschicht dazwischen und koordiniert APIs, Webhooks, Datenbanken, E-Mail, AI-Dienste und interne Systeme.

02
WORKFLOW

Trigger, Action und Node

Ein Trigger startet. Eine Action führt etwas aus. Ein Node ist ein einzelner Verarbeitungsschritt im Workflow.

Webhook [Trigger] → Edit Fields [Node] → IF [Node] → E-Mail [Action]
Mehr Details

Ein guter Workflow beantwortet: Was startet ihn? Welche Daten kommen hinein? Welche Regeln gelten? Was kommt heraus? Was passiert bei Fehlern? Wer ist Owner?

03
DATEN

Items, JSON und Expressions

n8n reicht strukturierte Daten zwischen Nodes weiter. Häufig liegen sie als JSON-basierte Items vor; Expressions lesen dynamisch Werte daraus.

{ "name": "Anna", "budget": 7500 } {{$json.name}} → Anna
Mehr Details

JSON besteht aus Key-Value-Paaren und kann Strings, Numbers, Booleans, Arrays und Objects enthalten. Wenn du nicht weißt, was ein Node als Input erhält, wird Debugging unnötig schwer.

04
HTTP

Webhook und Execution

Ein Webhook ist ein HTTP-Endpunkt, der ein Ereignis empfängt. Jede konkrete Workflow-Ausführung ist eine Execution.

POST /webhook/bais-academy-modul-01 ↓ Execution #1 → Nodes → Response
Test vs Production Webhook

/webhook-test/... dient der Entwicklung. /webhook/... ist für aktive Production Workflows. Ein häufiger Anfängerfehler ist, die Test-URL in eine echte Anwendung einzubauen.

05
LIFECYCLE

Demo ≠ PoC ≠ Production

Ein Workflow, der einmal grün läuft, ist noch kein produktionsfähiger Prozess. Production braucht Kontrollen für Fehler, Betrieb und Änderungen.

IDEA → DESIGN → BUILD → TEST → SECURE → DEPLOY → MONITOR → MAINTAIN
Production-Check

Validation, Authentication, Error Handling, Retry, Timeout, Logging, Monitoring, Recovery, Dokumentation und Ownership gehören in professionelle Automationen.

06
SECURITY

Credentials & Security Boundary

Secrets gehören in Credential Stores oder sichere Umgebungsvariablen. Externe Eingaben werden an einer Vertrauensgrenze geprüft, bevor sie interne Systeme erreichen.

INTERNET [untrusted] ↓ Validation / Security Boundary ↓ Backend → n8n → Database / API
BAIS Architektur

Für die BAIS Website ist das Muster bewusst: Browser → Cloudflare Function → Validierung → n8n. Dadurch hängt die öffentliche Webseite nicht blind direkt an internen Integrationen.
