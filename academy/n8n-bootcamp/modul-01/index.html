01
MENTAL MODEL

Was n8n wirklich ist

n8n ist eine Orchestrierungs- und Integrationsplattform: Ein Ereignis startet einen kontrollierten Datenfluss zwischen Systemen.

Ereignis
→
Workflow
→
Ergebnis
Vertiefung öffnen
Wichtig

n8n ersetzt nicht automatisch CRM, Datenbank oder Backend. Es verbindet und koordiniert sie.

Business-Beispiel

Kontaktformular → prüfen → Lead bewerten → CRM → Follow-up → Logging.

Bevor du Nodes auswählst, definierst du Prozessstart, Input, Regeln, Output, Fehlerpfad und Owner.

02
LIFECYCLE

Vom Prozess zum Workflow

Ein professioneller Workflow beginnt mit Prozessverständnis und endet nicht beim ersten grünen Lauf.

DISCOVERY → DESIGN → BUILD → TEST → SECURE → DEPLOY → MONITOR → MAINTAIN
Vertiefung öffnen

Discovery: Was soll automatisiert werden? Design: Welche Systeme, Regeln und Grenzen? Build: Nodes und Datenmapping. Test: Normal- und Fehlerfälle. Secure: Secrets, Input, Rechte. Deploy: Production. Monitor: Fehler und KPIs. Maintain: Änderungen kontrollieren.

03
BAUSTEINE

Trigger, Action und Node

Trigger startet. Action tut etwas. Node ist der einzelne Verarbeitungsschritt, der Daten erhält und weitergibt.

Webhook [TRIGGER] → Edit Fields [NODE] → IF [NODE] → E-Mail [ACTION]
Vertiefung öffnen
BegriffFrageBeispiel
TriggerWas startet?Webhook, Schedule, neue E-Mail
NodeWas passiert mit Daten?Set, IF, Merge, Code
ActionWelche Wirkung entsteht?API aufrufen, Mail senden, DB aktualisieren
04
DATENMODELL

Items und JSON

n8n transportiert strukturierte Datensätze. JSON ist dabei eines der wichtigsten Formate.

Item 1 → {"name":"Anna","budget":7500} Item 2 → {"name":"Mehmet","budget":3200}
Vertiefung öffnen

JSON kann Strings, Numbers, Booleans, Arrays und Objects enthalten. Ein Node kann ein oder viele Items verarbeiten. Du musst immer wissen: Welche Struktur kommt hinein, welche Struktur soll heraus?

Mini-Übung

Finde Key und Value in {"company":"BAIS","active":true}. Lösung: Keys = company/active; Values = BAIS/true.

05
DYNAMISCHE DATEN

Expressions und Datenreferenzen

Expressions lesen Werte dynamisch aus dem aktuellen oder einem anderen Node-Kontext.

{{$json.name}} → aktueller Name {{$json.budget}} → aktuelles Budget
Vertiefung öffnen

Wenn eine Expression undefined liefert, prüfst du zuerst den Input des Nodes. Nicht raten. Datenpfad ansehen, Feldnamen prüfen, Typen kontrollieren.

Merksatz

Expression-Probleme sind sehr oft Datenstruktur-Probleme.

06
HTTP

Webhooks als Eingangstor

Ein Webhook ist ein HTTP-Endpunkt. Externe Systeme können damit einen Workflow ereignisgesteuert starten.

POST /webhook/bais-academy-modul-01 Content-Type: application/json ↓ {"name":"Max","email":"max@example.com","budget":7500}
Vertiefung öffnen

Test: /webhook-test/... für Entwicklung. Production: /webhook/... für aktive Workflows. Prüfe Methode, URL, Content-Type, Body, Statuscode und Response.

07
OBSERVABILITY

Executions verstehen

Jeder konkrete Workflow-Lauf ist eine Execution. Sie ist deine wichtigste Spur beim Debugging.

Execution #1842 Webhook OK Validate OK Transform OK IF OK Respond OK
Vertiefung öffnen

Wenn es keine Execution gibt, liegt der Fehler meist vor oder am Trigger. Wenn eine Execution existiert und Node 4 fehlschlägt, untersuchst du Node 4 Input, Konfiguration, Error und Output.

08
SECRETS

Credentials und Environment Variables

API Keys, Tokens und Passwörter gehören nicht als Klartext in öffentliche Dateien oder frei sichtbare Workflow-Felder.

Workflow → Credential Store → API Environment → API_BASE_URL / ENVIRONMENT / Konfiguration
Vertiefung öffnen

Least Privilege, getrennte Service Accounts, Rotation und getrennte Development-/Production-Werte gehören zum professionellen Betrieb. Secrets dürfen auch nicht versehentlich in Logs landen.

09
BETRIEBSMODELL

Cloud vs Self-hosted

Managed Cloud reduziert Betriebsaufwand. Self-hosted bietet mehr Kontrolle, verschiebt aber Verantwortung zu dir.

Vertiefung öffnen
ManagedSelf-hosted
Betriebstärker beim Anbieterstärker bei dir
Kontrollebegrenzthoch
Updates/Backupsteilweise integriertselbst planen
Securitygeteiltmehr Eigenverantwortung

Unser n8n läuft auf eigener RepoCloud-Instanz. Damit müssen wir Deployment, Secrets, Monitoring und Workflow-Betrieb bewusst gestalten.

10
SECURITY ARCHITECTURE

Security Boundary

Externe Daten sind untrusted. Eine Vertrauensgrenze prüft Input, Identität, Rechte oder Bot-Schutz, bevor interne Systeme handeln.

INTERNET [UNTRUSTED] ↓ Cloudflare / Validation / Policy ↓ n8n ↓ Database / API / E-Mail
Vertiefung öffnen

Bei BAIS ist das Zielmuster: Browser → Backend/Validation → n8n. So wird n8n nicht unnötig direkt zur offenen Steuerfläche interner Systeme.

11
DEBUGGING

Nicht raten – Datenfluss verfolgen

Professionelles Debugging folgt einer festen Reihenfolge.

INPUT → TRIGGER → EXECUTION → NODE → OUTPUT
Vertiefung öffnen

Keine Execution? Endpoint, Methode, Aktivierung, Request. Execution vorhanden? Ersten fehlerhaften Node finden. 401? Authentifizierung. 422? Payload gegen Validierung prüfen. undefined? Datenstruktur/Expression prüfen.

Trainer-Regel

Du musst Fehler absichtlich erzeugen und anschließend reproduzierbar reparieren können.
