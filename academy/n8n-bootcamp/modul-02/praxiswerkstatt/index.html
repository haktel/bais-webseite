Items, JSON & Expressions unter Produktionsdruck

Jetzt musst du Daten lesen, normalisieren und skalieren. Reale Produktionsmuster zeigen, warum Item Count, Datentypen, Nested Data und stabile Contracts keine Anfänger-Details sind.

FALL 01

Stepstone · 2–3 Mio. Dokumente/Monat

Bei Millionen Dokumenten wird aus „ein Item“ sofort eine Kapazitätsfrage.

Quelle →
1 Item1 API Action?
100 Items100 Actions?
10kBatching
2–3 Mio.Operations

Deine Aufgabe

  1. Vergleiche 1 Item mit Array vs 100 einzelne Items.
  2. Welche Nodes laufen pro Item?
  3. Wo gehört Batch Size hin?
  4. Wie erkennst du unerwartet 50.000 Items vor einem API-Node?

Break/Fix

Ein upstream Node erzeugt statt 500 plötzlich 50.000 Items. Definiere Guard, Batch und Alert.

Musterlösung öffnen

Vor teuren Side-Effect-Nodes Item Count prüfen. Große Mengen kontrolliert batchen. Unexpected volume → Guard/Alert statt 50.000 unkontrollierter Requests.

FALL 02

Formula Bot · heterogene Datenquellen normalisieren

Formula Bot beschreibt Connectoren für PDFs, Excel, Analytics und Datenbanken. Unterschiedliche Quellen müssen in ein stabiles internes Modell überführt werden.

Deine Aufgabe

  1. Excel: customer_id; DB: customerId. Ein internes Feld definieren.
  2. Fehlende ID nasıl behandelt?
  3. String "129.90" in Number umwandeln.
  4. Empty array und null unterscheiden.

Break/Fix

PDF parser liefert {customer:{id:"C1"}}, Excel liefert {customer_id:"C1"}. Baue beide auf customerId.

Musterlösung öffnen
{"source":"pdf","customerId":"C1","records":[],"warnings":[]}

Source-spezifische Mapping-Schicht vor Business Logic. Fehlende Pflicht-ID → Reject/Review.

FALL 04

Vodafone · Expression oder Code?

Vodafone beschreibt eine Kombination aus visueller Automation und Code. Ziel: Code dort, wo er echten Mehrwert bringt.

Quelle →
Expressionein Feld lesen
Edit FieldsMapping
Codekomplexe Regeln
Sub-WorkflowReuse

Entscheide

  1. $json.customer.email → Expression oder Code?
  2. 20 Felder renamen → Edit Fields oder Code?
  3. Komplexe Array-Transformation →?
  4. Wiederkehrende Normalisierung in 8 Workflows →?

Break/Fix

Ein Code Node enthält Mapping, API call, retry ve logging in 250 Zeilen. Zerlege Verantwortlichkeiten.

Musterlösung öffnen

Einfaches Lesen → Expression. Transparente Mapping-Arbeit → Edit Fields. Komplexe Transformation → Code. Wiederverwendbare Verantwortung → Sub-Workflow.

Pflichtaufgabe

  1. Definiere Canonical Lead JSON.
  2. Normalisiere name/email/budget/source.
  3. Teste String/Number/null.
  4. Splitte Tags Array nur wenn nötig.
  5. Merge CRM lookup mit Input anhand leadId.
  6. Dokumentiere 6 Testfälle.

Ready to Teach

Erkläre warum „grüner Workflow“ trotzdem falsche Daten schreiben kann, wenn Typen und Pfade falsch sind.

Referenzlösung öffnen
{"leadId":"L-1001","name":"Mina Yilmaz","email":"mina@example.com","budget":7500,"source":"web","tags":["automation"]}

Validation vor Side Effect. Merge nach stabiler Domain-ID, nicht nach zufälliger Position.
