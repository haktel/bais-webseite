MODUL 04 · PRAXISWERKSTATT

Authentication, Credentials & OAuth2 in echten Integrationen

Ein Workflow ist nur so sicher wie seine Identität. Du lernst nicht nur Token-Namen, sondern entscheidest Credential-Typ, Scope, Rotation, Refresh und Fehlerpfad.

IDENTITYWer ruft auf?
CREDENTIALWie weist er sich aus?
SCOPEWas darf er?
LIFECYCLERotate · Refresh · Revoke
Regel: Secret-Werte niemals in Workflow JSON, Browser oder Logs. In Übungen modellieren wir nur Credential-Typ, Scope und Lifecycle.
FALL 01

API Key · einfacher, aber langfristig verantwortungsvoll

Viele APIs akzeptieren statische API Keys. Der technische Aufwand ist klein; Rotation, Scope und Leakage-Risiko bleiben trotzdem real.

Quelle: Stripe API Keys →
n8n Credential
→
HTTP Header
→
API Gateway
→
Scope Check
→
Action

Deine Aufgabe

  1. Key nereye kaydedilir?
  2. Header mı query parameter mı tercih?
  3. Prod/test key nasıl ayrılır?
  4. Rotation sonrası workflow kesintisiz nasıl güncellenir?

Break/Fix

Bir geliştirici API key'i Code Node içine yazdı ve workflow export edildi. Incident response adımlarını sırala.

Musterlösung öffnen

Key credential store'da. Secret source control'den çıkarılır, key revoke/rotate edilir, history/log exposure kontrol edilir ve yeni credential reference ile workflow test edilir.

FALL 02

Bearer Token · token taşıyan request

Bearer token request header içinde yetki taşır. Token'ı gören kişi çoğu sistemde token süresince aynı yetkiyi kullanabilir.

Quelle: RFC 6750 →
Credential
→
Authorization: Bearer …
→
Resource Server
→
Claims/Scope
→
Response

Deine Aufgabe

  1. Token neden loglanmamalı?
  2. Expiry nasıl ele alınır?
  3. 401 ve 403 farkı?
  4. Token scope fazla genişse risk nedir?

Break/Fix

Token geçerli ama required scope yok. 401 mı 403 mü? Workflow ne yapmalı?

Musterlösung öffnen

401 çoğunlukla authentication problemi; 403 authenticated ama izin yok durumu. Scope yoksa blind retry çözmez; permission/configuration düzeltilmelidir.

FALL 03

OAuth2 Authorization Code Flow

OAuth 2.0 authorization code flow, kullanıcı onayıyla erişim yetkisi devretmek için temel bir modeldir.

Quelle: OAuth 2.0 RFC 6749 →
User
→
Authorization Server
→
Code
→
Token Endpoint
→
Access Token

Deine Aufgabe

  1. Authorization endpoint ile token endpoint farkı?
  2. Authorization code neden direkt API token değildir?
  3. Redirect URI neden kesin eşleşmeli?
  4. Client secret nerede kalmalı?

Break/Fix

Callback URI yanlış. Kullanıcı login oluyor ama n8n token alamıyor. Debug sırasını yaz.

Musterlösung öffnen

Redirect URI registration, client ID, authorization URL, token URL, scope ve credential config sırayla kontrol edilir. Secret browser'a verilmez.

FALL 04

Refresh Token · uzun ömürlü entegrasyon

Kısa ömürlü access token ile daha uzun ömürlü refresh mekanizması, yeniden kullanıcı login'i olmadan token yenilemeyi sağlar.

Quelle: OAuth Refreshing Access Token →
Access Token expired
→
Refresh Token
→
Token Endpoint
→
New Access Token
→
Retry request

Deine Aufgabe

  1. Refresh token neden access token'dan daha hassas olabilir?
  2. Refresh fail olursa ne yapılır?
  3. Infinite refresh loop nasıl önlenir?
  4. Revoked consent nasıl görünür?

Break/Fix

API 401, refresh succeeds, retry still 401. Workflow kaç kez daha denemeli?

Musterlösung öffnen

Sınırlı refresh/retry. Sürekli 401 varsa credential invalid/revoked kabul edilip operator action gerekir. Sonsuz token-refresh döngüsü yok.

FALL 05 · CAPSTONE

Multi-System Integration · CRM + Mail + Storage

Bir workflow CRM'e yazıyor, mail gönderiyor ve object storage'a dosya yüklüyor. Her sistem farklı credential modeli kullanıyor.

CRM OAuth2
Mail OAuth2
Storage Key
Webhook Secret
↓
n8n Credentials · getrennte Identitäten
↓
Least Privilege + Rotation + Audit

Pflichtaufgabe

  1. Her entegrasyon için ayrı credential tanımla.
  2. Read vs write scope ayır.
  3. Rotation planı yaz.
  4. 401/403/expired/revoked testleri oluştur.
  5. Hangi alanlar loglanabilir, hangileri asla?

Ready to Teach

Neden „tek admin token ile her şeyi çalıştırmak“ başlangıçta kolay, production'da tehlikelidir?

Referenzlösung öffnen

Service başına minimum yetkili credential. Environment ayrımı. Secret değerleri log dışı. Rotation/revoke prosedürü ve başarısız auth için operator-visible alarm.
