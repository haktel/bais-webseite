FALL 01

Webhook Spoofing + Replay

Bir payment webhook'u public endpoint'e geliyor. Saldırgan sahte payload gönderiyor veya eski geçerli eventi tekrar oynatıyor.

Quelle: Stripe Webhook Signatures →
Raw Body
+
Signature
→
Verify
→
Fresh/EventId?
→
Process Once

Deine Aufgabe

  1. HMAC/signature secret nerede tutulur?
  2. Timestamp tolerance?
  3. eventId dedupe?
  4. Invalid signature logunda payload tutulmalı mı?

Break/Fix

Signature doğru ama event 10 dakika önce işlendi. Replay path'i block et.

Musterlösung öffnen

Signature + freshness + persistent eventId dedupe. Secret credential store'da; raw secret/log yok. Invalid/replayed event side effect'e ulaşmaz.

FALL 02

SSRF · User URL ile internal metadata erişimi

Workflow kullanıcıdan URL alıp HTTP Request yapıyor. Target http://169.254.169.254/latest/meta-data/.

Quelle: OWASP SSRF →
User URL
→
Parse Host
→
Allowlist / IP Check
→
Redirect Recheck
→
Request

Deine Aufgabe

  1. localhost/127/10/172.16-31/192.168/169.254 ne olur?
  2. HTTP vs HTTPS policy?
  3. DNS rebinding?
  4. Redirect private target'a giderse?

Break/Fix

Başlangıç host allowlisted ama 302 redirect private IP'ye gidiyor. İkinci target'ı validate et.

Musterlösung öffnen

Arbitrary URL yerine destination allowlist tercih edilir. Scheme/host/IP/private ranges ve redirect targets tekrar doğrulanır; network egress layer ek savunma sağlar.

FALL 03

Secret Leakage · execution logs ve exports

Bir Code Node API token'ı JSON output'a ekliyor; execution data ve workflow export üzerinden yayılabilir.

Quelle: OWASP Logging →
Credential Store
→
Use Secret
→
NO output
→
Redacted Logs
→
Audit Metadata

Deine Aufgabe

  1. Token leak olursa first actions?
  2. Git history?
  3. Execution retention?
  4. Email/phone masking?

Break/Fix

Authorization header debugging için loglandı. Güvenli debugging tasarla.

Musterlösung öffnen

Secret revoke/rotate, exposure scope review, logs/history temizliği mümkünse, safe metadata ile debugging. Credential value hiçbir generic log/output'a yazılmaz.

FALL 04

Community Node / Supply Chain

Bir community node production credential'lara erişecek. Convenience ile trust aynı şey değildir.

Quelle: n8n Community Node Risks →
Sourcecode/repo
Maintaineractivity
Permissionsdata/credentials
Versionpin/update

Deine Aufgabe

  1. Core node alternatifi var mı?
  2. Package permissions?
  3. Version pinning?
  4. Security advisory/update process?

Break/Fix

Auto-update sonrası node davranışı değişti. Staged update + regression test planı yaz.

Musterlösung öffnen

Third-party code explicit trust decision'dır. Necessity review, source/maintainer/dependency review, least privilege, pinned version, test/staged rollout ve rollback.

FALL 05 · CAPSTONE

Security Incident · credential compromise

Monitoring, CRM service credential'ının beklenmeyen IP/işlem davranışı gösterdiğini tespit ediyor. Aynı credential 12 workflow tarafından kullanılıyor.

Detect
→
Contain
→
Rotate/Revoke
→
Evidence
→
Recover

Incident çöz

  1. Hangi workflows/callers etkileniyor?
  2. Credential hemen revoke edilir mi?
  3. Business continuity nasıl sağlanır?
  4. Hangi logs/evidence korunur?
  5. Data exposure nasıl değerlendirilir?
  6. Lessons learned hangi controls'a dönüşür?

Ready to Teach

Defense in Depth'i bu incident üzerinden anlat: tek bir secret-control neden yeterli değil?

Referenzlösung öffnen

Containment + credential rotation, caller inventory, suspicious executions correlation, least-privilege replacement, impacted data review, monitored recovery. Sonrasında shared credential usage azaltılır ve service-specific identities oluşturulur.
