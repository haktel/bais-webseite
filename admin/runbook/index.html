6. Recovery Procedures

A · Website / Server Down

  1. Alert bestätigen und Incident eröffnen.
  2. DNS/TLS/CDN/Runtime/DB prüfen.
  3. Letzten Deploy und Provider-Status prüfen.
  4. Sicherste Recovery-Aktion wählen.
  5. Smoke-Test und Monitoring validieren.
[WEBSITE_RECOVERY_COMMANDS_OR_PROVIDER_STEPS]

B · Database Corrupted / Lost

  1. Riskante Writes stoppen.
  2. Letzten validen Backup-Point bestimmen.
  3. Restore zunächst in Validation Target.
  4. Schema/Data/Tenant-Isolation prüfen.
  5. Restore promoten und Writes freigeben.
[DATABASE_RECOVERY_COMMANDS_OR_PROVIDER_STEPS]

C · Bad Deployment / Rollback

  1. Weitere Deployments stoppen.
  2. Bad Release und Last Good Release bestimmen.
  3. DB-Migration-Kompatibilität prüfen.
  4. Rollback oder Hotfix durchführen.
  5. Smoke-Test und Beobachtungsfenster.
[ROLLBACK_COMMANDS_OR_CICD_STEPS]
